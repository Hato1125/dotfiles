# コミットメッセージ

## リポジトリの指定

- 呼び出し時の文章で名前・パスを指定する。例: `対象: repo-a repo-b`。
  名前・相対パスは呼び出し時の現在地基準とし、空白を含む指定は引用符で囲む。
- 未指定なら現在地が属するリポジトリを使う。リポジトリ外なら直下を調べ、
  リポジトリが一つだけあれば使う。ゼロ・複数なら対象の指定を求める。
- 指定先が見つからない・曖昧・アクセス不能なら、理由を示して再指定を求める。
- 対象は Git 作業ツリーのルート全体とし、同じルートは重複処理しない。
  複数指定は指定順に、以下の確認・判断・出力をリポジトリごとに独立して行う。

## 対象の変更

- ステージ済みの変更があれば、その差分のみを対象とする。
- なければ、未ステージの変更と未追跡ファイルを対象とする。
  追跡済みファイルの削除も含め、未追跡の無視対象は除外する。
- Git の状態と対象の差分・内容を確認する。同じファイルでも対象外の差分は混ぜない。
- 変更がなければ、その旨を伝えてそのリポジトリの処理を終える。
  競合や読み取り不能などで判断できない場合は、障害を伝えて確定案を出さない。
  いずれも他の対象リポジトリの処理は続ける。

## 判断

- ファイル数ではなく、目的と依存関係で分割・一括を判断する。
- 別々にレビュー・取り消しできる異なる目的の変更は分割する。
- 同じ目的の実装・テスト・文書や、分離すると不整合になる変更はまとめる。
- 分割時は、対象の差分を重複・漏れなく割り当て、依存先を先に並べる。
  同じファイルを分ける場合は、部分ステージが必要な箇所を特定する。

## メッセージ

- 確認できた変更の目的を、簡潔で具体的な件名にする。
- 言語・形式はユーザー指定を優先し、なければリポジトリの規約、直近の履歴に従う。
- 説明文（コミット本文）は、ユーザーが明示的に求めた場合のみ付ける。
  分割案の各コミットと一括案のすべてに適用する。
- Co-Authored-By などのトレーラーは付けない。

## 出力

リポジトリごとにルートパスを示して出力を分ける。
各出力の最初に対象範囲と、分割・一括の判断理由を簡潔に示す。
ファイルのパスは、そのリポジトリのルート基準とする。
メッセージはコードブロックに入れ、判断理由や対象ファイルの説明と分離する。

- 分割する場合:
  1. コミット順に、ステージするファイルのパスとメッセージを示す。
     部分ステージが必要なら、各コミットに含める差分も明記する。
     ステージ済みが対象なら、その差分の割り当てを示し、
     未ステージの差分を混ぜるファイル全体の再ステージは勧めない。
  2. 最後に「一つにまとめる場合」として、同じ対象全体のメッセージを示す。
- 一括にする場合: 対象全体のメッセージのみを示し、分割案は出さない。

## 制限

提案のみを行い、ファイル・ステージ状態・履歴を変更しない。
